# Glossary

> **Verified:** 2026-11-15 · Terms use the current official names from the [feature verification matrix](FEATURE-VERIFICATION.md).

This glossary gives a short, plain-language definition of each term the academy uses, across four areas: AWS foundations, generative AI, Amazon Bedrock and AgentCore, and infrastructure as code and DevOps. Each entry ends with the chapter that teaches the term, where you find the precise version and the official sources. Entries are alphabetical; AgentCore services are listed under A as "AgentCore …", and a status such as preview or maintenance mode is stated wherever it affects a design decision.

## A

- **A2A (Agent-to-Agent protocol)** — A protocol for agents to discover and call each other; each agent describes itself in an Agent Card. AgentCore Runtime can serve it, and AgentCore Gateway can front A2A services as HTTP targets. _See:_ [Agentic AI, tool calling and multi-agent architectures](00-foundations/generative-ai-fundamentals/06-agents-tool-calling-multi-agent.md) · [AgentCore Runtime](01-amazon-bedrock/agentcore/02-agentcore-runtime.md)
- **Action group** — In Agents Classic, a set of actions an agent may take, defined by an OpenAPI schema or function details plus an optional Lambda function that runs them. On AgentCore the equivalent is tools exposed through AgentCore Gateway. _See:_ [Amazon Bedrock Agents Classic](01-amazon-bedrock/agents/01-agents-classic.md) · [Agents Classic versus AgentCore, and migrating](01-amazon-bedrock/agents/03-agents-classic-vs-agentcore.md)
- **Agent** — An application that uses a foundation model in a loop: it reads the request, decides on a step, calls a tool, reads the result and repeats until the task is done. _See:_ [Agentic AI, tool calling and multi-agent architectures](00-foundations/generative-ai-fundamentals/06-agents-tool-calling-multi-agent.md) · [Agent orchestration patterns](09-advanced-topics/07-agent-orchestration-patterns.md)
- **AgentCore (Amazon Bedrock AgentCore)** — The AWS platform for building, deploying and operating agents with any framework and any model. It is a set of modular services, such as Runtime, harness, Gateway, Identity and Memory, that you use together or separately. _See:_ [AgentCore overview](01-amazon-bedrock/agentcore/01-agentcore-overview.md)
- **AgentCore Browser** — A managed cloud browser that an agent drives to open pages, fill in forms and extract information. It works with automation frameworks such as Playwright. _See:_ [AgentCore Browser and Code Interpreter](01-amazon-bedrock/agentcore/08-agentcore-browser-and-code-interpreter.md)
- **AgentCore Code Interpreter** — An isolated sandbox in which an agent runs code it has written, in Python, JavaScript or TypeScript. _See:_ [AgentCore Browser and Code Interpreter](01-amazon-bedrock/agentcore/08-agentcore-browser-and-code-interpreter.md)
- **AgentCore Evaluations** — A service that scores agent sessions, traces and spans using LLM-as-judge evaluators, either built-in or your own. Evaluations run online, on demand or in batch. _See:_ [AgentCore Evaluations and Optimization](01-amazon-bedrock/agentcore/10-agentcore-evaluations-and-optimization.md) · [Model quality evaluation in production](09-advanced-topics/13-model-quality-evaluation.md)
- **AgentCore Gateway** — A single, secured entry point through which agents reach tools, other agents and models. It turns APIs and Lambda functions into MCP tools and combines them into one virtual MCP server. _See:_ [AgentCore Gateway](01-amazon-bedrock/agentcore/04-agentcore-gateway.md) · [MCP and tool integration on AWS](09-advanced-topics/09-mcp-and-tool-integration.md)
- **AgentCore harness** — A managed agent loop: you declare the model, system prompt and tools as configuration, and AgentCore runs the agent with each session in its own microVM. AWS recommends it as the path from Agents Classic. _See:_ [AgentCore harness](01-amazon-bedrock/agentcore/03-agentcore-harness.md) · [Agents Classic versus AgentCore, and migrating](01-amazon-bedrock/agents/03-agents-classic-vs-agentcore.md)
- **AgentCore Identity** — The service that gives each agent its own identity and stores the OAuth tokens and API keys the agent needs to call other services. _See:_ [AgentCore Identity](01-amazon-bedrock/agentcore/05-agentcore-identity.md)
- **AgentCore Memory** — A managed store that lets agents remember. Short-term memory keeps the events of a session; long-term memory keeps records extracted across sessions. _See:_ [AgentCore Memory](01-amazon-bedrock/agentcore/06-agentcore-memory.md)
- **AgentCore Observability** — Traces, metrics and logs for agents, emitted in an OpenTelemetry-compatible format and stored in Amazon CloudWatch. _See:_ [AgentCore Observability](01-amazon-bedrock/agentcore/07-agentcore-observability.md) · [Observability and tracing for GenAI](09-advanced-topics/12-observability-and-tracing.md)
- **AgentCore Optimization** — A service that uses real traces to recommend changes to system prompts and tool descriptions, then validates them with A/B tests. Its Insights feature is in preview. _See:_ [AgentCore Evaluations and Optimization](01-amazon-bedrock/agentcore/10-agentcore-evaluations-and-optimization.md)
- **AgentCore Payments** — A service that lets agents make small payments to paid APIs, MCP servers and content through wallet providers. Preview. _See:_ [AgentCore Payments, Web Search and Web Answer](01-amazon-bedrock/agentcore/12-agentcore-payments-and-web-search.md)
- **AgentCore Policy** — Deterministic rules, written in Cedar, that are evaluated on every tool call passing through an AgentCore Gateway. The default is deny, and a forbid rule always wins. _See:_ [AgentCore Policy](01-amazon-bedrock/agentcore/09-agentcore-policy.md)
- **AgentCore Runtime** — A serverless host for agent or tool code written with any framework and any model. Each session runs in its own microVM, and the Runtime speaks HTTP, MCP, A2A and AG-UI. _See:_ [AgentCore Runtime](01-amazon-bedrock/agentcore/02-agentcore-runtime.md)
- **Agentic retrieval** — Retrieval in which a model plans sub-queries, retrieves in several rounds, checks whether the results are sufficient and then answers with citations. It works only with a Managed Knowledge Base. _See:_ [Agentic retrieval with AgenticRetrieveStream](01-amazon-bedrock/agentic-retrieval/01-agentic-retrieval.md)
- **`AgenticRetrieveStream`** — The `bedrock-agent-runtime` operation that runs agentic retrieval and streams back results, trace events and, by default, a generated answer. It replaces `RetrieveAndGenerate` on a Managed Knowledge Base. _See:_ [Agentic retrieval with AgenticRetrieveStream](01-amazon-bedrock/agentic-retrieval/01-agentic-retrieval.md)
- **Agents Classic (Amazon Bedrock Agents Classic)** — The original Amazon Bedrock Agents service under its new name. It is in maintenance mode and closed to new customers since 2026-07-30; AWS recommends AgentCore for new agents. _See:_ [Amazon Bedrock Agents Classic](01-amazon-bedrock/agents/01-agents-classic.md) · [Agents Classic versus AgentCore, and migrating](01-amazon-bedrock/agents/03-agents-classic-vs-agentcore.md)
- **Amazon Kendra** — An AWS enterprise search service that can serve as the index behind a knowledge base. In maintenance mode since 2026-07-30, so the academy does not design new retrieval around it. _See:_ [Amazon Redshift, Amazon Kendra and AWS DMS](02-related-aws-services/databases/04-redshift-kendra-dms.md)
- **Amazon S3 Vectors** — Vector storage in Amazon S3: you keep vectors in vector indexes inside a vector bucket and query them by similarity. It is a quick-create vector store for customer-managed knowledge bases. _See:_ [Amazon S3 and Amazon S3 Vectors](02-related-aws-services/storage/01-amazon-s3-and-s3-vectors.md) · [Vector store selection](09-advanced-topics/02-vector-store-selection.md)
- **ANN (approximate nearest neighbor) search** — A way to find the vectors closest to a query vector quickly, by accepting a small loss of accuracy instead of comparing against every stored vector. _See:_ [Embeddings, vector search, semantic search and hybrid search](00-foundations/generative-ai-fundamentals/03-embeddings-and-vector-search.md) · [Vector store selection](09-advanced-topics/02-vector-store-selection.md)
- **Application inference profile** — An inference profile that you create to track the cost and usage of one application. It points to a model in one Region or to a cross-Region inference profile, and it can carry tags. _See:_ [Application inference profiles](01-amazon-bedrock/inference/05-application-inference-profiles.md)
- **`ApplyGuardrail`** — The `bedrock-runtime` operation that evaluates content against a guardrail without invoking a model, so you can guard any input or output. _See:_ [Amazon Bedrock Guardrails](01-amazon-bedrock/guardrails/01-guardrails.md)
- **Aspect** — In the AWS CDK, an operation applied to every construct in a scope during synthesis. Aspects are used to add tags or to check rules, such as requiring every bucket to be encrypted. _See:_ [Permissions and Aspects](04-infrastructure-as-code/aws-cdk/05-permissions-and-aspects.md)
- **Automated Reasoning checks** — A guardrail policy type that validates a model's answer against logical rules extracted from your own policy document. It uses formal logic, not pattern matching, and explains why an answer is valid or not. _See:_ [Automated Reasoning checks and guardrail enforcement](01-amazon-bedrock/guardrails/02-automated-reasoning-and-enforcement.md)
- **Availability Zone** — One or more discrete data centers in a Region with their own power and networking. Spreading resources across Availability Zones protects against the failure of one site. _See:_ [AWS global infrastructure: Regions, Availability Zones and the edge](00-foundations/aws-fundamentals/01-global-infrastructure.md)
- **AWS Agent Registry (AgentCore Registry)** — A governed catalog in which you publish agents, MCP servers, tools and skills as records, approve them, and let people and agents find them through hybrid search. _See:_ [AWS Agent Registry](01-amazon-bedrock/agentcore/11-agentcore-registry.md)
- **AWS managed key** — A KMS key in your account that an AWS service creates and manages for you, with an alias of the form `aws/service-name`. You cannot change its key policy or lifecycle. _See:_ [AWS KMS and encryption](00-foundations/security/04-kms-encryption.md)
- **AWS owned key** — A KMS key that an AWS service keeps in its own account and uses to encrypt your data by default. You pay nothing for it and cannot view, audit or manage it. _See:_ [AWS KMS and encryption](00-foundations/security/04-kms-encryption.md)

## B

- **Backend** — In Terraform, the place where state is stored and locked, for example an S3 bucket. A remote backend lets a team and a pipeline share one state. _See:_ [State, remote backends and state locking](04-infrastructure-as-code/terraform/04-state-backends-locking.md)
- **Base model** — A foundation model as packaged by its provider and ready to use, as opposed to a custom model that you created from it. _See:_ [Model providers and the model catalog](01-amazon-bedrock/foundation-models/01-model-providers-and-catalog.md)
- **Batch inference** — Asynchronous inference on many prompts at once. You put input files in Amazon S3, start a job, and collect the outputs from S3; it is priced below on-demand inference. _See:_ [Batch inference](01-amazon-bedrock/inference/08-batch-inference.md)
- **Bedrock API key** — A bearer token that you can use instead of SigV4 signing to call Amazon Bedrock. Short-term keys inherit the permissions of the IAM principal that generated them; long-term keys are for exploration only. _See:_ [Endpoints, APIs and authentication](01-amazon-bedrock/overview/02-endpoints-apis-and-authentication.md)
- **`bedrock-mantle`** — The second inference endpoint, which serves the OpenAI-compatible APIs and the Anthropic Messages API. You need it only for server-side tools such as Web Search, background inference, Projects and Workspaces, or mantle-only models. _See:_ [Endpoints, APIs and authentication](01-amazon-bedrock/overview/02-endpoints-apis-and-authentication.md) · [Projects, Workspaces and the Web Search tool](01-amazon-bedrock/overview/04-projects-workspaces-and-web-search.md)
- **`bedrock-runtime`** — The main inference endpoint, recommended by AWS for new applications. It serves Converse, InvokeModel, the OpenAI-compatible APIs and the Anthropic Messages API. _See:_ [Endpoints, APIs and authentication](01-amazon-bedrock/overview/02-endpoints-apis-and-authentication.md)
- **Blueprint** — In Amazon Bedrock Data Automation, a reusable definition of the fields to extract from one class of file, such as an invoice, with a data type and a plain-language description for each field. _See:_ [Amazon Bedrock Data Automation](01-amazon-bedrock/data-automation/01-bedrock-data-automation.md)
- **Bootstrap** — The one-time preparation of an AWS account and Region for the AWS CDK. `cdk bootstrap` deploys a stack, by default `CDKToolkit`, with the S3 bucket, ECR repository and IAM roles that deployments use. _See:_ [Bootstrap and deployment](04-infrastructure-as-code/aws-cdk/06-bootstrap-and-deployment.md)

## C

- **Cache point** — A marker in a prompt that tells Amazon Bedrock to cache everything before it: the `cachePoint` field in Converse, called a cache checkpoint in the documentation. The prefix must reach a model-specific minimum number of tokens. _See:_ [Prompt caching](01-amazon-bedrock/prompt-caching/01-prompt-caching.md)
- **CDK (AWS Cloud Development Kit)** — A framework for defining AWS infrastructure in a programming language such as TypeScript. Your code is synthesized into CloudFormation templates, which CloudFormation then deploys. _See:_ [Apps, stacks and constructs](04-infrastructure-as-code/aws-cdk/01-apps-stacks-constructs.md) · [Synthesis and CloudFormation templates](04-infrastructure-as-code/aws-cdk/03-synthesis-and-cloudformation.md)
- **Cedar** — An open-source language from AWS for writing authorization rules as `permit` and `forbid` statements. AgentCore Policy uses it to decide which tool calls a Gateway allows; the documentation also describes Dogwood, a Cedar-compatible superset. _See:_ [AgentCore Policy](01-amazon-bedrock/agentcore/09-agentcore-policy.md)
- **Change set** — A preview, produced by CloudFormation, of what a stack update would add, modify or delete. You review it and then execute or discard it. _See:_ [Change sets and drift detection](04-infrastructure-as-code/cloudformation/04-change-sets-and-drift.md)
- **Chunking** — Splitting documents into smaller pieces before embedding them, so that retrieval returns focused passages. Strategies include fixed-size, hierarchical and semantic chunking. _See:_ [Ingestion, parsing and chunking](01-amazon-bedrock/knowledge-bases/04-ingestion-parsing-chunking.md) · [Chunking strategies](09-advanced-topics/03-chunking-strategies.md)
- **CloudFormation (AWS CloudFormation)** — The AWS service that creates, updates and deletes resources together as a stack, from a declarative JSON or YAML template. The AWS CDK and AWS SAM both deploy through it. _See:_ [Template anatomy: parameters, mappings, conditions, resources and outputs](04-infrastructure-as-code/cloudformation/01-template-anatomy.md) · [Terraform, AWS CDK, CloudFormation, SAM and Pulumi compared](04-infrastructure-as-code/comparison/02-tool-comparison.md)
- **CloudFormation Guard** — A policy-as-code tool with its own rule language for checking templates and resource configurations. Guard rules can also run as CloudFormation Hooks. _See:_ [Hooks and CloudFormation Guard](04-infrastructure-as-code/cloudformation/05-hooks-and-guard.md)
- **CloudTrail data event** — A CloudTrail record of an operation performed on or in a resource, such as reading an S3 object. Unlike management events, data events are not logged by default and cost extra. _See:_ [Amazon CloudWatch and AWS CloudTrail](00-foundations/aws-fundamentals/04-cloudwatch-cloudtrail.md) · [AWS CloudTrail for Bedrock](02-related-aws-services/security/05-cloudtrail-for-bedrock.md)
- **Construct** — The building block of a CDK app: a class that represents one or more CloudFormation resources and their configuration. Constructs come in three levels, L1, L2 and L3. _See:_ [Apps, stacks and constructs](04-infrastructure-as-code/aws-cdk/01-apps-stacks-constructs.md) · [L1, L2 and L3 constructs](04-infrastructure-as-code/aws-cdk/02-l1-l2-l3-constructs.md)
- **Content filter** — A guardrail policy that detects harmful text or images in prompts and responses in predefined categories, including prompt attacks, at a strength you set for each category. _See:_ [Amazon Bedrock Guardrails](01-amazon-bedrock/guardrails/01-guardrails.md)
- **Context window** — The maximum number of tokens a model can take into account in one request, counting the prompt, the conversation history and the output it generates. _See:_ [Tokens, context windows, and training versus inference](00-foundations/generative-ai-fundamentals/02-tokens-context-windows-inference.md)
- **Contextual grounding check** — A guardrail policy that scores a response for grounding (is it supported by the source you supplied?) and relevance (does it answer the question?) and blocks responses that fall below your thresholds. _See:_ [Amazon Bedrock Guardrails](01-amazon-bedrock/guardrails/01-guardrails.md) · [Retrieval-augmented generation (RAG)](00-foundations/generative-ai-fundamentals/04-rag-fundamentals.md)
- **Control plane** — The APIs that create and configure resources, for example the `bedrock` and `bedrock-agentcore-control` namespaces. The data plane is where those resources are then used. _See:_ [What Amazon Bedrock is: services, namespaces and planes](01-amazon-bedrock/overview/01-what-is-amazon-bedrock.md)
- **Converse API** — The `Converse` and `ConverseStream` operations on `bedrock-runtime`. They give one message format that works across models, with built-in support for tool use and guardrails. _See:_ [The Converse API](01-amazon-bedrock/inference/01-converse-api.md)
- **Credential provider** — In AgentCore Identity, a resource that holds the settings for obtaining an OAuth token or API key for an external service, so that secrets stay out of agent code. _See:_ [AgentCore Identity](01-amazon-bedrock/agentcore/05-agentcore-identity.md)
- **Cross-Region inference** — Letting Amazon Bedrock route an inference request to another Region, through an inference profile, to use capacity there. Geo profiles stay within a geography; Global profiles can use any supported commercial Region. _See:_ [Cross-Region inference: Geo and Global profiles](01-amazon-bedrock/inference/04-cross-region-inference.md) · [Cross-Region considerations and data residency](09-advanced-topics/11-cross-region-and-data-residency.md)
- **Custom Model Import** — A feature for bringing a model you customized elsewhere, such as in Amazon SageMaker AI, into Amazon Bedrock and calling it with `InvokeModel`. It is billed per Custom Model Unit. _See:_ [Custom Model Import and on-demand custom model deployment](01-amazon-bedrock/foundation-models/04-custom-model-import.md)
- **Customer managed key** — A KMS key that you create and control. You set its key policy, rotation and deletion, and its use is recorded in CloudTrail. _See:_ [AWS KMS and encryption](00-foundations/security/04-kms-encryption.md) · [AWS KMS, Secrets Manager and Parameter Store](02-related-aws-services/security/02-kms-secrets-manager-parameter-store.md)
- **Customer-managed knowledge base** — A knowledge base for which you choose and operate the vector store, such as OpenSearch Serverless, Aurora PostgreSQL or S3 Vectors, and the ingestion settings. AWS now recommends the Managed Knowledge Base type. _See:_ [Customer-managed knowledge bases and vector stores](01-amazon-bedrock/knowledge-bases/03-customer-managed-knowledge-bases.md) · [Knowledge Bases overview: managed versus customer-managed](01-amazon-bedrock/knowledge-bases/01-knowledge-bases-overview.md)

## D

- **Data Automation (Amazon Bedrock Data Automation, BDA)** — A service that turns documents, images, audio and video into structured output, either in a standard form or shaped by your own blueprints. _See:_ [Amazon Bedrock Data Automation](01-amazon-bedrock/data-automation/01-bedrock-data-automation.md)
- **Data plane** — The APIs that use resources which already exist, such as `bedrock-runtime` for inference. The control plane is where those resources are created and configured. _See:_ [What Amazon Bedrock is: services, namespaces and planes](01-amazon-bedrock/overview/01-what-is-amazon-bedrock.md)
- **Data residency** — A requirement that data is stored and processed only in certain places. It decides whether you can use a Global inference profile or must keep to a Geo profile or a single Region. _See:_ [Cross-Region considerations and data residency](09-advanced-topics/11-cross-region-and-data-residency.md)
- **Data source (knowledge base)** — The connection from a knowledge base to the place your documents live, such as an S3 bucket or SharePoint, together with its ingestion settings. _See:_ [Ingestion, parsing and chunking](01-amazon-bedrock/knowledge-bases/04-ingestion-parsing-chunking.md) · [Managed Knowledge Base](01-amazon-bedrock/knowledge-bases/02-managed-knowledge-base.md)
- **Data source (Terraform)** — A read-only lookup of something that already exists, such as `aws_bedrock_foundation_model`. It supplies values to your configuration without managing the object. _See:_ [Providers, resources and data sources](04-infrastructure-as-code/terraform/01-providers-resources-data-sources.md)
- **Declarative** — A style of infrastructure as code in which you describe the end state you want and the tool works out the steps. The opposite style, imperative, lists the steps themselves. _See:_ [IaC concepts: declarative versus imperative, state, graphs, drift and idempotency](04-infrastructure-as-code/comparison/01-iac-concepts.md)
- **Denied topic** — A guardrail policy in which you describe a subject in plain language and the guardrail blocks prompts or responses about it. _See:_ [Amazon Bedrock Guardrails](01-amazon-bedrock/guardrails/01-guardrails.md)
- **Distillation** — Fine-tuning a smaller, cheaper student model on answers produced by a larger teacher model, so that the student performs better on your use case. _See:_ [Fine-tuning and model customization](00-foundations/generative-ai-fundamentals/05-fine-tuning-and-customization.md) · [Model customization: fine-tuning, reinforcement fine-tuning and distillation](01-amazon-bedrock/foundation-models/03-model-customization.md)
- **Drift** — A difference between the infrastructure that your code or state describes and what actually exists, usually caused by a manual change. _See:_ [IaC concepts: declarative versus imperative, state, graphs, drift and idempotency](04-infrastructure-as-code/comparison/01-iac-concepts.md) · [Post-deployment validation, monitoring and drift detection](07-devops-and-cicd/07-post-deploy-validation-and-drift.md)

## E

- **Embedding** — A list of numbers (a vector) that represents the meaning of a piece of text, an image or other content, so that similar content has nearby vectors. _See:_ [Embeddings, vector search, semantic search and hybrid search](00-foundations/generative-ai-fundamentals/03-embeddings-and-vector-search.md)
- **Embedding model** — A model whose output is an embedding instead of text. Queries and documents must be embedded with the same model for their vectors to be comparable. _See:_ [Embeddings, vector search, semantic search and hybrid search](00-foundations/generative-ai-fundamentals/03-embeddings-and-vector-search.md) · [Embedding model selection](09-advanced-topics/04-embedding-model-selection.md)
- **Envelope encryption** — Encrypting data with a data key and then encrypting that data key with a KMS key. Only the small data key is sent to AWS KMS, never the data itself. _See:_ [AWS KMS and encryption](00-foundations/security/04-kms-encryption.md)
- **Ephemeral resource** — A Terraform resource that exists only during a run, such as a temporary password. Terraform never writes it to state or plan files. _See:_ [Secrets management and policy as code](04-infrastructure-as-code/maintenance/04-secrets-and-policy-as-code.md)
- **Execution role** — An IAM role that a service assumes to act for you, for example the role a knowledge base uses to read your S3 bucket. Also called a service role. _See:_ [IAM roles, trust policies and cross-account access](00-foundations/security/02-iam-roles-and-trust.md) · [Identity, least privilege and IAM isolation for agents](06-security-governance/02-identity-and-least-privilege.md)

## F

- **Fallback model** — A second model that your application calls when the first one is throttled, unavailable or retired. _See:_ [Resilience, fallback models and model routing](08-cost-performance-and-reliability/06-resilience-fallback-and-model-routing.md) · [Model routing and fallback models](09-advanced-topics/10-model-routing-and-fallback.md)
- **Fine-tuning** — Further training of a base model on your own labeled examples. It adjusts the model's parameters and produces a custom model. _See:_ [Fine-tuning and model customization](00-foundations/generative-ai-fundamentals/05-fine-tuning-and-customization.md) · [Model customization: fine-tuning, reinforcement fine-tuning and distillation](01-amazon-bedrock/foundation-models/03-model-customization.md)
- **Flows (Amazon Bedrock Flows)** — A workflow builder that links prompts, models, knowledge bases, Lambda functions and other nodes into a fixed graph. You publish versions, point an alias at one and call it with `InvokeFlow`. Earlier name: Prompt flows. _See:_ [Amazon Bedrock Flows](01-amazon-bedrock/flows/01-bedrock-flows.md)
- **Foundation model (FM)** — A large model trained on a broad range of data that can handle many tasks, such as generating text or images or producing embeddings, without being trained for each one. _See:_ [Generative AI, foundation models and LLMs](00-foundations/generative-ai-fundamentals/01-generative-ai-and-foundation-models.md)

## G

- **Gateway endpoint** — A VPC endpoint for Amazon S3 or DynamoDB that works as a route-table target, not a network interface. It does not use PrivateLink. _See:_ [VPC endpoints and AWS PrivateLink](00-foundations/networking/03-vpc-endpoints-and-privatelink.md)
- **Gateway target** — A backend attached to an AgentCore Gateway. MCP targets, such as Lambda functions, OpenAPI specifications and MCP servers, become tools; HTTP targets are proxied directly; inference targets route to model providers. _See:_ [AgentCore Gateway](01-amazon-bedrock/agentcore/04-agentcore-gateway.md)
- **Generative AI** — AI that produces new content, such as text, images, audio or code, in response to a prompt. _See:_ [Generative AI, foundation models and LLMs](00-foundations/generative-ai-fundamentals/01-generative-ai-and-foundation-models.md)
- **Geo inference profile** — A system-defined cross-Region inference profile whose requests stay inside one geography. Its ID starts with a prefix such as `us.` or `eu.`. _See:_ [Cross-Region inference: Geo and Global profiles](01-amazon-bedrock/inference/04-cross-region-inference.md) · [Cross-Region considerations and data residency](09-advanced-topics/11-cross-region-and-data-residency.md)
- **Global inference profile** — A system-defined cross-Region inference profile, with the ID prefix `global.`, that can route a request to any supported commercial Region. It costs slightly less than a Geo profile. _See:_ [Cross-Region inference: Geo and Global profiles](01-amazon-bedrock/inference/04-cross-region-inference.md) · [Cross-Region considerations and data residency](09-advanced-topics/11-cross-region-and-data-residency.md)
- **GraphRAG** — A knowledge base option that stores entities and their relationships in an Amazon Neptune Analytics graph and follows them at query time, to connect facts spread across documents. _See:_ [Structured data retrieval and GraphRAG](01-amazon-bedrock/knowledge-bases/06-structured-data-and-graphrag.md)
- **Grounding** — Tying a model's answer to source material that you supply, so that each claim can be traced back to a retrieved passage. _See:_ [Retrieval-augmented generation (RAG)](00-foundations/generative-ai-fundamentals/04-rag-fundamentals.md)
- **Guardrail** — A resource in Amazon Bedrock Guardrails that holds your safety policies: content filters, denied topics, word filters, sensitive information filters, contextual grounding checks and Automated Reasoning checks. You apply a version of it to inference calls. _See:_ [Amazon Bedrock Guardrails](01-amazon-bedrock/guardrails/01-guardrails.md)
- **Guardrail enforcement** — Making a guardrail mandatory, through IAM condition keys or an enforced configuration for an account or organization, so that applications cannot call a model without it. _See:_ [Automated Reasoning checks and guardrail enforcement](01-amazon-bedrock/guardrails/02-automated-reasoning-and-enforcement.md) · [Governance at scale: Organizations, SCPs and guardrail enforcement](06-security-governance/06-governance-at-scale.md)

## H

- **Hallucination** — Output that reads as fact but is not supported by the model's input or by reality. Grounding and guardrail checks reduce it; they do not remove it. _See:_ [Retrieval-augmented generation (RAG)](00-foundations/generative-ai-fundamentals/04-rag-fundamentals.md) · [Generative AI, foundation models and LLMs](00-foundations/generative-ai-fundamentals/01-generative-ai-and-foundation-models.md)
- **Hook** — A CloudFormation feature that inspects a resource, stack or change set before provisioning and fails the operation or warns if it breaks your rules. Hooks can be Guard rules or Lambda functions. _See:_ [Hooks and CloudFormation Guard](04-infrastructure-as-code/cloudformation/05-hooks-and-guard.md)
- **Human-in-the-loop** — A design in which a person reviews or approves a step, such as a risky tool call, before the system continues. _See:_ [Human-in-the-loop workflows](09-advanced-topics/08-human-in-the-loop.md)
- **Hybrid search** — Search that combines semantic (vector) matching with keyword matching and merges the results. It is always on in a Managed Knowledge Base. _See:_ [Embeddings, vector search, semantic search and hybrid search](00-foundations/generative-ai-fundamentals/03-embeddings-and-vector-search.md) · [Hybrid search, reranking and metadata filtering](09-advanced-topics/05-hybrid-search-reranking-metadata-filtering.md)

## I

- **Idempotency** — The property that repeating an operation leaves the result unchanged. Applying infrastructure code that has not changed should change nothing. _See:_ [IaC concepts: declarative versus imperative, state, graphs, drift and idempotency](04-infrastructure-as-code/comparison/01-iac-concepts.md)
- **Identity-based policy** — A JSON policy attached to an IAM user, group or role that says what that identity may do. _See:_ [IAM fundamentals: principals, policies and evaluation](00-foundations/security/01-iam-fundamentals.md)
- **Import block** — A Terraform block that brings an existing resource under management as part of a normal plan and apply, in place of a one-off CLI command. _See:_ [Lifecycle rules, import, moved and removed blocks](04-infrastructure-as-code/terraform/07-lifecycle-import-moved-removed.md) · [Version upgrades, refactoring and importing existing resources](04-infrastructure-as-code/maintenance/05-upgrades-refactoring-import.md)
- **Inference** — Running a trained model to get an output from an input. Training builds the model; inference uses it, and it is what you pay for per token. _See:_ [Tokens, context windows, and training versus inference](00-foundations/generative-ai-fundamentals/02-tokens-context-windows-inference.md)
- **Inference parameters** — Request settings, such as temperature, top-p and maximum output tokens, that change how varied or how long a response is. _See:_ [The Converse API](01-amazon-bedrock/inference/01-converse-api.md) · [Tokens, context windows, and training versus inference](00-foundations/generative-ai-fundamentals/02-tokens-context-windows-inference.md)
- **Inference profile** — A resource that names a model and the Region or Regions that requests can be routed to. System-defined profiles (Geo or Global) give cross-Region inference; application inference profiles add cost tracking. _See:_ [Cross-Region inference: Geo and Global profiles](01-amazon-bedrock/inference/04-cross-region-inference.md) · [Application inference profiles](01-amazon-bedrock/inference/05-application-inference-profiles.md)
- **Infrastructure as code (IaC)** — Managing cloud resources through versioned files that a tool applies, instead of through manual changes in the console. _See:_ [IaC concepts: declarative versus imperative, state, graphs, drift and idempotency](04-infrastructure-as-code/comparison/01-iac-concepts.md) · [Terraform, AWS CDK, CloudFormation, SAM and Pulumi compared](04-infrastructure-as-code/comparison/02-tool-comparison.md)
- **Ingestion job** — One run that syncs a data source into a knowledge base. It parses, chunks, embeds and indexes the documents added, changed or deleted since the last run. _See:_ [Ingestion, parsing and chunking](01-amazon-bedrock/knowledge-bases/04-ingestion-parsing-chunking.md)
- **Intelligent prompt routing** — A single endpoint, called a prompt router, that predicts which model in a family will answer each request best and routes to it, to balance quality and cost. - **Interface endpoint** — A VPC endpoint that places a network interface with a private IP address in your subnet, so that calls to an AWS service stay on the AWS network. It is powered by PrivateLink. _See:_ [VPC endpoints and AWS PrivateLink](00-foundations/networking/03-vpc-endpoints-and-privatelink.md) · [Private connectivity for Bedrock: interface endpoints and PrivateLink](02-related-aws-services/networking/01-private-connectivity-for-bedrock.md)
- **Intrinsic function** — A built-in CloudFormation function, such as `Ref`, `Fn::GetAtt` or `Fn::Sub`, that computes a value when the stack is deployed. _See:_ [Intrinsic functions](04-infrastructure-as-code/cloudformation/02-intrinsic-functions.md)
- **`InvokeModel`** — The `bedrock-runtime` operation that sends a request body in the model's own native format. `InvokeModelWithResponseStream` is its streaming form. _See:_ [InvokeModel and streaming APIs](01-amazon-bedrock/inference/02-invokemodel-and-streaming.md)

- **Knowledge base** — A resource in Amazon Bedrock Knowledge Bases that ingests your documents and returns the passages relevant to a query. ## L

- **Large language model (LLM)** — A foundation model trained on text that generates language one token at a time, which lets it write, summarize, translate and answer questions. _See:_ [Generative AI, foundation models and LLMs](00-foundations/generative-ai-fundamentals/01-generative-ai-and-foundation-models.md)
- **Least privilege** — Granting only the permissions needed for a task, and no more. _See:_ [IAM fundamentals: principals, policies and evaluation](00-foundations/security/01-iam-fundamentals.md) · [Identity, least privilege and IAM isolation for agents](06-security-governance/02-identity-and-least-privilege.md)
- **LLM-as-judge** — Evaluation in which a second model scores another model's answers against criteria and explains each score. _See:_ [Model evaluation and model selection](00-foundations/generative-ai-fundamentals/07-model-evaluation-and-selection.md) · [Model and RAG evaluation](01-amazon-bedrock/model-evaluation/01-model-evaluation.md)
- **Long-term memory** — In AgentCore Memory, records such as facts, preferences and summaries that memory strategies extract from conversations and keep across sessions. _See:_ [AgentCore Memory](01-amazon-bedrock/agentcore/06-agentcore-memory.md)

## M

- **Managed Knowledge Base** — A knowledge base in which Amazon Bedrock runs ingestion, storage, indexing and retrieval for you, with managed embedding and reranking models. - **Marketplace (Amazon Bedrock Marketplace)** — A catalog of additional models that you subscribe to and deploy to an endpoint managed by Amazon SageMaker AI, then call through `InvokeModel` or Converse. _See:_ [Amazon Bedrock Marketplace](01-amazon-bedrock/foundation-models/05-bedrock-marketplace.md)
- **MCP (Model Context Protocol)** — An open protocol that standardizes how applications provide tools and context to models. An agent's MCP client lists and calls the tools that an MCP server offers. _See:_ [MCP and tool integration on AWS](09-advanced-topics/09-mcp-and-tool-integration.md) · [Agentic AI, tool calling and multi-agent architectures](00-foundations/generative-ai-fundamentals/06-agents-tool-calling-multi-agent.md)

- **Memory strategy** — A setting on an AgentCore Memory resource that decides what to extract from raw conversation events into long-term memory. - **Metadata filtering** — Restricting retrieval to chunks whose metadata matches conditions that you set, such as a tenant ID or a document type. _See:_ [Retrieval, reranking and metadata filtering](01-amazon-bedrock/knowledge-bases/05-retrieval-reranking-filtering.md) · [Multitenant RAG](09-advanced-topics/06-multitenant-rag.md)
- **microVM** — A lightweight virtual machine. AgentCore Runtime starts a dedicated one for each session, which isolates its CPU, memory and file system from every other session. _See:_ [AgentCore Runtime](01-amazon-bedrock/agentcore/02-agentcore-runtime.md)
- **Model access** — Permission to call a model. The old request step is gone: access is on by default when your IAM principal has the AWS Marketplace subscribe permissions, although some models remain gated. _See:_ [Model access and subscriptions](01-amazon-bedrock/overview/03-model-access-and-subscriptions.md)
- **Model customization** — Adjusting a base model's parameters with your own data to create a custom model. Amazon Bedrock offers supervised fine-tuning, reinforcement fine-tuning and distillation. _See:_ [Model customization: fine-tuning, reinforcement fine-tuning and distillation](01-amazon-bedrock/foundation-models/03-model-customization.md) · [Fine-tuning and model customization](00-foundations/generative-ai-fundamentals/05-fine-tuning-and-customization.md)
- **Model evaluation** — Measuring and comparing model outputs to choose a model or to check quality. Amazon Bedrock runs automatic, LLM-as-judge, human and RAG evaluation jobs. _See:_ [Model and RAG evaluation](01-amazon-bedrock/model-evaluation/01-model-evaluation.md) · [Model evaluation and model selection](00-foundations/generative-ai-fundamentals/07-model-evaluation-and-selection.md)
- **Model invocation logging** — A setting per account and Region, off by default, that delivers the full request and response of model calls on `bedrock-runtime` to CloudWatch Logs or Amazon S3. _See:_ [CloudWatch and Bedrock-specific observability](02-related-aws-services/observability/01-cloudwatch-and-bedrock-observability.md) · [Logging, audit and compliance evidence](06-security-governance/07-logging-audit-and-compliance.md)
- **Model lifecycle** — The states a model passes through on Amazon Bedrock: Active, Legacy and End-of-Life. - **Model unit (MU)** — The unit in which you buy Provisioned Throughput. One model unit delivers a set number of input and output tokens per minute for a given model. _See:_ [Provisioned Throughput](01-amazon-bedrock/inference/07-provisioned-throughput.md)
- **Module** — In Terraform, a directory of configuration that you call with inputs and that returns outputs, so that one tested building block can be reused. _See:_ [Modules](04-infrastructure-as-code/terraform/03-modules.md) · [Module and construct versioning](04-infrastructure-as-code/maintenance/02-module-and-construct-versioning.md)
- **Moved block** — A Terraform block that records a resource's new address after a rename or a move into a module, so that Terraform updates state and does not destroy and recreate the resource. _See:_ [Lifecycle rules, import, moved and removed blocks](04-infrastructure-as-code/terraform/07-lifecycle-import-moved-removed.md) · [Version upgrades, refactoring and importing existing resources](04-infrastructure-as-code/maintenance/05-upgrades-refactoring-import.md)
- **Multi-agent collaboration** — Several agents working on one task, typically a supervisor that delegates to specialists. The Agents Classic feature of this name is in maintenance mode. _See:_ [Multi-agent collaboration](01-amazon-bedrock/agents/02-multi-agent-collaboration.md) · [Agent orchestration patterns](09-advanced-topics/07-agent-orchestration-patterns.md)

- **PrivateLink (AWS PrivateLink)** — The AWS technology behind interface endpoints. ## R

- **Stack** — The unit of deployment in CloudFormation: a set of resources created, updated and deleted together from one template. A CDK app defines one or more stacks. _See:_ [Apps, stacks and constructs](04-infrastructure-as-code/aws-cdk/01-apps-stacks-constructs.md) · [Template anatomy: parameters, mappings, conditions, resources and outputs](04-infrastructure-as-code/cloudformation/01-template-anatomy.md)
- **StackSet** — A CloudFormation feature that deploys one template as stacks into many accounts and Regions in a single operation. _See:_ [Nested stacks and StackSets](04-infrastructure-as-code/cloudformation/03-nested-stacks-and-stacksets.md) · [Multi-account and multi-Region deployments](04-infrastructure-as-code/maintenance/06-multi-account-multi-region.md)
- **State** — Terraform's record of the real resources it manages and their attributes. Terraform compares state with your configuration to build a plan. _See:_ [State, remote backends and state locking](04-infrastructure-as-code/terraform/04-state-backends-locking.md)
- **State locking** — Preventing two Terraform runs from writing the same state at once. The S3 backend locks natively with `use_lockfile = true`; DynamoDB locking is deprecated. _See:_ [State, remote backends and state locking](04-infrastructure-as-code/terraform/04-state-backends-locking.md)
- **Streaming** — Returning a response piece by piece as it is generated, through `ConverseStream` or `InvokeModelWithResponseStream`, so that the user sees the first words sooner. _See:_ [InvokeModel and streaming APIs](01-amazon-bedrock/inference/02-invokemodel-and-streaming.md) · [Latency optimization](08-cost-performance-and-reliability/03-latency-optimization.md)
- **Subnet** — A range of IP addresses in a VPC that sits in one Availability Zone. It is public if its route table sends traffic to an internet gateway, and private otherwise. _See:_ [VPCs and subnets](00-foundations/networking/01-vpc-and-subnets.md) · [Public and private networking](00-foundations/networking/02-public-private-networking.md)
- **Synthesis** — The CDK step, run with `cdk synth`, that executes your app and produces CloudFormation templates and assets. Nothing is deployed. _See:_ [Synthesis and CloudFormation templates](04-infrastructure-as-code/aws-cdk/03-synthesis-and-cloudformation.md)
- **System prompt** — Instructions that set a model's role and rules for a whole conversation, sent separately from the user's messages; in Converse it is the `system` field. _See:_ [The Converse API](01-amazon-bedrock/inference/01-converse-api.md)

## T

- **Template** — A JSON or YAML file that declares the resources of a CloudFormation stack, with optional parameters, mappings, conditions and outputs. _See:_ [Template anatomy: parameters, mappings, conditions, resources and outputs](04-infrastructure-as-code/cloudformation/01-template-anatomy.md)
- **Terraform** — HashiCorp's declarative infrastructure-as-code tool. You write configuration in HCL, and Terraform plans and applies changes through providers and records them in state. _See:_ [Terraform, AWS CDK, CloudFormation, SAM and Pulumi compared](04-infrastructure-as-code/comparison/02-tool-comparison.md) · [Providers, resources and data sources](04-infrastructure-as-code/terraform/01-providers-resources-data-sources.md)
- **Throttling** — Rejection of requests that exceed a quota or the capacity available. Common remedies are retries with backoff, cross-Region inference and a fallback model. _See:_ [Quotas, rate limits and throttling](08-cost-performance-and-reliability/05-quotas-rate-limits-and-throttling.md) · [Resilience, fallback models and model routing](08-cost-performance-and-reliability/06-resilience-fallback-and-model-routing.md)
- **Time to first token (TTFT)** — The delay between sending a request and receiving the first piece of a streamed response. It largely decides how responsive a chat feels. _See:_ [Latency and token economics](00-foundations/generative-ai-fundamentals/08-latency-and-token-economics.md) · [Latency optimization](08-cost-performance-and-reliability/03-latency-optimization.md)
- **Token** — The unit a model reads and writes: a word, part of a word or a punctuation mark. Pricing, quotas and context windows are all counted in tokens. _See:_ [Tokens, context windows, and training versus inference](00-foundations/generative-ai-fundamentals/02-tokens-context-windows-inference.md)
- **Token vault** — The AgentCore Identity store for OAuth tokens and API keys, encrypted with KMS. A credential is released only to the agent and user combination that obtained it. _See:_ [AgentCore Identity](01-amazon-bedrock/agentcore/05-agentcore-identity.md)
- **Tool calling** — A model's ability to ask for a function to be run by returning its name and arguments; your code runs it and sends back the result. Also called function calling or tool use. _See:_ [Agentic AI, tool calling and multi-agent architectures](00-foundations/generative-ai-fundamentals/06-agents-tool-calling-multi-agent.md) · [The Converse API](01-amazon-bedrock/inference/01-converse-api.md)
- **Trace** — The recorded path of one request through a system, made of timed spans such as model calls and tool calls. _See:_ [Observability and tracing for GenAI](09-advanced-topics/12-observability-and-tracing.md) · [AgentCore Observability](01-amazon-bedrock/agentcore/07-agentcore-observability.md)
- **Trust policy** — The resource-based policy on an IAM role that says which principals may assume the role. _See:_ [IAM roles, trust policies and cross-account access](00-foundations/security/02-iam-roles-and-trust.md)

## U

- **`use_lockfile`** — The S3 backend argument that turns on native state locking by writing a `.tflock` object next to the state. It replaces the DynamoDB lock table. _See:_ [State, remote backends and state locking](04-infrastructure-as-code/terraform/04-state-backends-locking.md)

## V

- **Vector store** — A database that stores embeddings and finds the ones nearest to a query vector. Examples are OpenSearch Serverless, Aurora PostgreSQL with pgvector and Amazon S3 Vectors. _See:_ [Embeddings, vector search, semantic search and hybrid search](00-foundations/generative-ai-fundamentals/03-embeddings-and-vector-search.md) · [Vector store selection](09-advanced-topics/02-vector-store-selection.md)
- **VPC (virtual private cloud)** — A logically isolated virtual network in your AWS account, in one Region, in which you define IP address ranges, subnets and routing. _See:_ [VPCs and subnets](00-foundations/networking/01-vpc-and-subnets.md)
- **VPC endpoint** — A private connection from a VPC to an AWS service that does not use the internet. The two main types are interface endpoints and gateway endpoints. _See:_ [VPC endpoints and AWS PrivateLink](00-foundations/networking/03-vpc-endpoints-and-privatelink.md)

## W

- **Web Search tool** — A built-in, AWS-hosted tool that lets supported models fetch current information from the web and cite it. It is available through the Responses API on `bedrock-mantle` only. _See:_ [Projects, Workspaces and the Web Search tool](01-amazon-bedrock/overview/04-projects-workspaces-and-web-search.md)
- **Workload identity** — The identity that AgentCore Identity gives an agent or other workload, independent of where it runs. The agent uses it to prove who it is when it requests credentials from the token vault. _See:_ [AgentCore Identity](01-amazon-bedrock/agentcore/05-agentcore-identity.md) · [Identity, least privilege and IAM isolation for agents](06-security-governance/02-identity-and-least-privilege.md)
- **Workspace (Amazon Bedrock)** — The same isolation boundary as a Project, used with the Anthropic Messages API on `bedrock-mantle`. _See:_ [Projects, Workspaces and the Web Search tool](01-amazon-bedrock/overview/04-projects-workspaces-and-web-search.md)
- **Workspace (Terraform)** — A named, separate state for the same configuration. It is one way, with limits, to manage several environments. _See:_ [Workspaces and environment strategies](04-infrastructure-as-code/terraform/05-environments-and-workspaces.md)
- **Write-only argument** — A Terraform resource argument whose value is passed to the provider during a run but never stored in state or plan files. It is meant for secrets. _See:_ [Secrets management and policy as code](04-infrastructure-as-code/maintenance/04-secrets-and-policy-as-code.md)

## Names that changed

If you learned from older material, these are the names most likely to mislead you. Every row comes from the [feature verification matrix](FEATURE-VERIFICATION.md).

| Old name | Current name | What happened |
|:--|:--|:--|
| Amazon Bedrock Agents | Amazon Bedrock Agents Classic | Renamed. In maintenance mode and closed to new customers since 2026-07-30; AWS recommends AgentCore, with the harness as the migration path. |
| Prompt flows | Amazon Bedrock Flows | Renamed. |
| Knowledge base (one type, with a vector store you create) | Managed Knowledge Base, or customer-managed knowledge base | Two types since Managed Knowledge Base became generally available on 2026-06-17. The older kind is now called customer-managed. |
| `RetrieveAndGenerate` (one-call RAG) | `AgenticRetrieveStream` | Not supported on a Managed Knowledge Base, where `AgenticRetrieveStream` replaces it. It still works on customer-managed knowledge bases. |
| "Request model access" | Model access (on by default) | The request step was removed on 2025-10-15. |
| Cross-Region inference profile (`us.`, `eu.`) | Geo (Geographic) inference profile | Global (`global.`) profiles were added, so the geography-bound kind is now called Geo. |
| AgentCore starter toolkit | AgentCore CLI (`@aws/agentcore`) | The starter toolkit is marked deprecated in its repository. |
| DynamoDB state locking (`dynamodb_table`) | S3 native locking (`use_lockfile = true`) | Native locking is generally available since Terraform 1.11; DynamoDB locking is deprecated. |
| tfsec | Trivy | tfsec was folded into Trivy. |
| CDK for Terraform (CDKTF) | None | Archived on 2025-12-10; HashiCorp no longer maintains it. |
| Bedrock L2 constructs in `@cdklabs/generative-ai-cdk-constructs` | `@aws-cdk/aws-bedrock-alpha` (experimental), or L1 constructs | The Bedrock L2 constructs in the older package are deprecated. |
